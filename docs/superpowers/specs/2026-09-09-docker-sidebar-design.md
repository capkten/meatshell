# Docker 容器与镜像监控设计

日期：2026-09-09

状态：设计已确认，待制定实现计划

## 1. 目标

在 MeatShell 左侧资源监控区域增加 Docker 摘要，并提供一个类似进程监控的独立只读窗口，用于查看当前目标上的容器和镜像。

Docker 数据源跟随当前活动目标：欢迎页和本地终端查看本机 Docker；SSH 会话查看当前 SSH 服务器 Docker；Telnet 和串口会话查看本机 Docker。第一版只支持 Docker CLI，不支持 Podman、Docker Compose 或 Kubernetes。

## 2. 范围与明确不做的事情

### 本次包含

- 左侧 Docker 摘要卡片：目标名称、连接状态、容器总数、运行中容器数、镜像数。
- 点击摘要卡片打开独立 Docker 监控窗口。
- 容器和镜像两个页签。
- 容器筛选：全部、运行中、已停止。
- 搜索过滤：大小写不敏感，输入为空时恢复全部结果。
- 容器列表按名称、完整 ID、镜像名称或标签匹配。
- 镜像列表按仓库、标签或镜像 ID 匹配。
- 点击条目查看只读详情。
- 可见时每 5 秒自动刷新，并提供手动刷新；隐藏时暂停自动刷新。
- 区分 Docker 未安装、权限不足、服务未启动、命令失败和正常空列表。

### 本次不包含

- 启动、停止、重启、删除容器。
- 拉取、删除、重新打标签或推送镜像。
- 进入容器、执行容器命令或查看日志。
- 环境变量展示。
- Podman 兼容层。
- 修改现有会话配置、连接方式、进程监控和系统监控行为。

## 3. 用户界面

### 3.1 左侧摘要

Docker 卡片放在现有资源监控区，与 CPU、内存、GPU、磁盘和进程摘要保持同一套停靠、折叠和主题行为。

卡片只展示紧凑摘要，不展示容器列表，以免服务器容器很多时挤占终端空间。摘要包括：

- 当前数据源：本机或当前 SSH 服务器。
- Docker 可用状态。
- 容器总数。
- 运行中容器数。
- 镜像数。

当前目标没有 Docker CLI 时，卡片完全隐藏。Docker CLI 存在但无法访问守护进程、权限不足或查询失败时，卡片保留并展示简短错误原因，必要时提供重试入口。

切换活动标签后，摘要立即切换到新目标；如果新目标没有安装 Docker，则只隐藏该目标下的卡片，不影响其他标签的状态。

### 3.2 Docker 监控窗口

窗口沿用进程监控窗口的独立窗口生命周期、主题同步和模型更新方式，包含：

- 标题和当前数据源。
- “容器”和“镜像”页签。
- 当前页的搜索框。
- 容器页的全部、运行中、已停止筛选。
- 手动刷新按钮。
- 可滚动列表。
- 选中条目的只读详情区域。

搜索在当前已加载快照上执行，不会因为每次键入都重新执行 Docker 命令。搜索与容器状态筛选可以同时生效。列表显示当前匹配数量与总数量；没有匹配项时显示明确的空结果状态。搜索框清空后恢复当前快照的完整列表。

### 3.3 详情

容器详情展示：

- 完整容器 ID。
- 镜像。
- 命令。
- 创建时间。
- 端口映射。
- 挂载。
- 网络。

镜像详情展示：

- 镜像 ID。
- 仓库和标签。
- 大小。
- 创建时间。

不读取、不解析、不展示环境变量，避免把密码、Token 等信息带入 UI 模型或日志。

## 4. 数据源与执行方式

### 4.1 目标选择

Docker 查询目标由当前活动标签映射得到：

| 当前场景 | Docker 目标 | 执行方式 |
| --- | --- | --- |
| 欢迎页 | 本机 | 本机 Docker CLI |
| 本地终端 | 本机 | 本机 Docker CLI |
| SSH 会话 | 当前 SSH 服务器 | 复用当前已认证 SSH 会话 |
| Telnet 会话 | 本机 | 本机 Docker CLI |
| 串口会话 | 本机 | 本机 Docker CLI |

远程查询不得重新建立一套独立 SSH 登录；应复用当前 SSH 会话的认证状态和辅助执行通道，避免密码重复询问、连接状态分裂和会话关闭后残留请求。

### 4.2 Docker CLI 数据

本机和远程统一通过 Docker CLI 获取结构化数据，不解析面向人类展示的表格文本。列表查询使用 Docker 的 JSON 模板输出；选中条目后使用对应的 `docker inspect` 获取详情。搜索只在解析后的 Rust 数据上执行，用户输入不会直接拼接进 Docker 命令。

查询至少包含以下信息：

- Docker CLI/守护进程可用性探测。
- 所有容器摘要，包括停止的容器。
- 所有镜像摘要。
- 选中容器或镜像的详情。

容器和镜像列表查询可以分别报告错误。如果一类资源查询成功而另一类失败，成功的页签仍可用，失败的页签显示自己的错误状态。

### 4.3 异步与生命周期

Docker 查询运行在后台，不阻塞 Slint UI 线程。结果通过现有 UI 事件回调路径回到 UI 线程。

窗口可见或左侧摘要需要数据时，按 5 秒间隔刷新；窗口和摘要都不可见时暂停定时刷新。手动刷新立即触发一次查询，但不会启动多个并行的同目标查询。

每个查询携带目标标识和递增请求代次。活动标签、SSH 会话或目标发生变化时，旧查询结果即使晚到也必须被丢弃，不能覆盖新目标的 UI 数据。窗口关闭时停止对窗口模型的更新。

## 5. 建议的模块边界

### Docker 领域模块

新增独立 Docker 领域模块，负责：

- 本机和远程命令执行抽象。
- JSON 输出解析。
- 容器、镜像和详情数据结构。
- 搜索与状态过滤。
- Docker 错误分类。

该模块不直接操作 Slint 控件，便于使用固定 JSON 样本进行单元测试。

### SSH 命令与事件

在现有 SSH 命令和事件通道中增加 Docker 查询/结果消息，使远程查询复用已有 SSH worker 和辅助 channel 生命周期。连接断开时，Docker 查询应与其他辅助资源查询一起结束或失效。

### 应用状态与资源 UI

- `WindowState` 增加 Docker 监控窗口和选中详情的状态。
- 侧边栏刷新逻辑根据活动标签选择本机或远程 Docker 快照。
- 资源 UI 转换逻辑只负责把领域快照映射成 Slint 模型，不在 UI 层解析命令输出。
- Docker 窗口模型与进程窗口一样共享主题，并通过 UI 线程同步。

### Slint UI

新增 Docker 窗口 UI 文件，复用进程窗口的窗口布局、列表、搜索输入、页签和滚动交互风格。所有列表更新、错误状态和详情切换都通过已有 Slint callback 和 UI 线程路径完成。

## 6. 错误和状态模型

错误状态至少分为：

1. `NotInstalled`：找不到 Docker 可执行文件。左侧面板隐藏。
2. `PermissionDenied`：当前用户无权访问 Docker socket 或远程命令被拒绝。面板保留并显示原因。
3. `DaemonUnavailable`：Docker CLI 存在但守护进程未运行或不可连接。面板保留并显示原因。
4. `CommandFailed`：其他非零退出或远程执行失败。面板保留并显示原因。
5. `ParseFailed`：命令返回内容无法解析为预期 JSON。面板保留并显示数据错误，不在 UI 中展示完整原始输出。
6. `Empty`：查询成功但没有容器或镜像。显示空状态，不视为错误。

错误文本面向用户且简洁；完整诊断信息继续遵循现有错误日志策略，不把敏感命令输出直接展示在窗口中。手动刷新可重新尝试失败查询。

## 7. 测试策略

### 领域单元测试

- 容器 JSON 和镜像 JSON 的解析。
- 详情 JSON 的字段映射，包括端口、挂载和网络。
- 容器运行状态筛选。
- 容器和镜像的大小写不敏感搜索。
- 空搜索、无匹配和组合筛选。
- 未安装、权限、守护进程不可用、命令失败和 JSON 解析失败的分类。
- 本机/远程目标映射。
- 旧请求结果在目标代次变化后被丢弃。

### UI 和回归验证

- `cargo fmt --all -- --check`。
- `cargo clippy --all-targets -- -D warnings`。
- `cargo test --locked`。
- `cargo check` 验证 Slint 与 Rust 回调连接。
- 手工验证本机 Docker、SSH 远程 Docker、未安装 Docker、权限不足和 Docker 服务未启动场景。
- 回归验证现有 CPU、内存、GPU、磁盘、进程监控、SSH 连接、Telnet、串口和窗口主题行为不受影响。

## 8. 验收标准

功能完成时，必须满足：

- 当前活动目标正确决定 Docker 数据来源。
- 未安装 Docker 时左侧不出现误导性空面板。
- Docker 有权限或服务问题时用户能看到明确原因。
- 容器和镜像都能在独立窗口中查看、搜索和筛选。
- 搜索不会发起每键一次的远程 Docker 命令，也不会泄露环境变量。
- 窗口隐藏时不持续刷新；切换目标时旧数据不会串到新目标。
- 现有功能和既有本地 fork 约定保持不变，尤其是会话配置、SSH 生命周期、系统资源监控和更新地址。
- 格式检查、Lint、测试和编译检查全部通过。
